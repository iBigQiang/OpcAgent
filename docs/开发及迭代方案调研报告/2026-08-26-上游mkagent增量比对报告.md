## 二、比对方法学 —— 两个必须记录的坑

### 坑 1：沙箱内 `git fetch` 静默失败，导致差点误判"上游无更新"

首次执行 `git fetch upstream --tags` **退出码为 0、无任何输出**，此时 `git merge-base HEAD upstream/main` 恰好等于 `upstream/main`，表面结论是"上游零更新"。

实际是沙箱阻断了网络：`.git/FETCH_HEAD` 时间戳停留在 **2026-08-12**，而当天是 08-26，`upstream/main` 用的是 14 天前的缓存引用。

**规避方式**：判断上游是否有更新，用 `git ls-remote upstream refs/heads/main` 直连查询权威 SHA，不依赖任何本地 remote-tracking ref。

### 坑 2：共享 `.git` 下 `FETCH_HEAD` 被并发会话覆写，不可作为判据

本仓库是 worktree（`git-common-dir` = `D:/AiCode/MkAgent/.git`），`FETCH_HEAD` 与主检出及其他 worktree 共享。比对期间观察到 `cat FETCH_HEAD` 显示 `a148f98 craft-sources-mcp of iBigQiang/OpcAgent`，而 `git log -1 FETCH_HEAD` 却解析出 `242306a` —— 同一时刻两个读数不一致，说明有其他会话正在并发写入。

**规避方式**：`FETCH_HEAD` 一律不作判据；更新 remote-tracking ref 用显式 refspec：
```bash
git fetch upstream '+refs/heads/*:refs/remotes/upstream/*' --tags
```

## 三、`2c22a07` dialog 桥接 —— 唯一值得融合的代码改动

上游改动 `apps/electron/src/main/index.ts` 中两个 IPC handler，实际含**两个独立变更**，价值截然不同。

### 变更 A：窗口回退链 —— 我方还缺，建议融合

```diff
- BrowserWindow.fromWebContents(event.sender)!
+ BrowserWindow.fromWebContents(event.sender)
+   || BrowserWindow.getFocusedWindow()
+   || BrowserWindow.getAllWindows()[0]
```

原写法用非空断言 `!` 掩盖了 `fromWebContents()` 返回 `null` 的可能。一旦为 null，`dialog.showMessageBox(null, spec)` 会抛错，capability 调用 reject，对话框不显示。

**风险真实性核查**：已确认 `bootstrap-preload.cjs`（唯一注册 dialog capability 的 preload，见 `apps/electron/src/preload/bootstrap.ts:39-40`）只挂载在 `window-manager.ts:258` 的正规 BrowserWindow 上；Browser pane 使用独立的 `browser-toolbar-preload.cjs`（`browser-pane-manager.ts:449`），不注册 dialog。

因此**不存在"从 BrowserView/webview 发起 dialog"的高频路径**。真实触发场景收窄为：窗口正在销毁 / 已销毁，而 agent 侧的 dialog IPC 仍在飞行中的竞态。

**判定**：低频但真实的健壮性缺口，改动极小、无行为副作用，值得融合。

**融合时的两个注意点**：
1. `apps/electron/tsconfig.json` **不 extends 根 tsconfig**，未开启 `noUncheckedIndexedAccess`，故 `getAllWindows()[0]` 类型为 `BrowserWindow`，上游写法可直接通过 typecheck。
2. 但运行时若所有窗口均已关闭，`getAllWindows()[0]` 为 `undefined`。更严谨的做法是显式处理该分支，而非依赖 Electron 对 falsy 首参的内部嗅探。

### 变更 B：返回值收窄 —— 我方已独立修复，无需照搬

上游修复前后与我方现状对比：

| | `showOpenDialog` 返回 |
|---|---|
| 上游修复前 | `.then(result => result.filePaths)` → **数组**（违反契约） |
| 我方现状（`dd078875`，iBigQiang，08-11） | 完整 Electron result → `{canceled, filePaths, bookmarks?}` |
| 上游修复后 | `{canceled: …, filePaths: …}` |

契约定义在 `packages/server-core/src/transport/capabilities.ts`：

```ts
requestClientConfirmDialog(…):  Promise<{ response: number }>
requestClientOpenFileDialog(…): Promise<{ canceled: boolean; filePaths: string[] }>
```

我方返回完整 result **结构上已满足契约**（多余字段 `checkboxChecked` / `bookmarks` 均可 structured-clone，运行时无问题）。上游改为显式挑字段属于代码整洁度改进（减少跨进程数据量与意外耦合），**不是 bug 修复**，功能等价。

**判定**：可选。若追求与契约声明严格一致可一并收窄，但无功能收益。
